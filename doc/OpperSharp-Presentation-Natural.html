OpperSharp

C# SDK för Opper AI API

En produktionsklar lösning för .NET-utvecklare

Intro - lugnt tempo, inte stressa Börja med kort bakgrund: Opper har Python och TypeScript, men vi .NET-utvecklare hade inget bra alternativ Viktigt att få med: detta är inte bara en wrapper, det är en fullständig SDK som faktiskt ger värde Om någon frågar: ja, jag byggde den med hjälp av AI, men all arkitektur och design är genomtänkt

Problemet vi hade

Opper AI har bara officiella SDKs för:

  • Python
  • TypeScript/JavaScript

För .NET? Direkt REST API-anrop...

Berätta snabbt om Opper - AI-plattform med Functions, RAG, Chat, etc Poängen: varför ska vi sitta och hantera HTTP-anrop, JSON-serialisering, felhantering själva? REST API funkar ju, men det är typ 90% mer kod för varje operation Och ingen IntelliSense, ingen type safety... du fattar

Så vad är OpperSharp då?

En komplett SDK som ger dig:

  • Full API-täckning - allt som finns i Python SDK
  • Type safety och IntelliSense
  • Async/await-stöd (naturligtvis)
  • Några extra features också
Viktigt: jag har verkligen gått igenom Python SDK ordentligt och implementerat allt Extra features = bulk operations, CRUD för functions/indexes, retry-logik Async/await - självklart, det är ju 2026 Type safety: slipp runtime-fel, få feedback direkt i VS

Hur det är byggt

10 separata projekt, modulärt uppbyggt:

  • OpperSharp.Core - HTTP-klient och bas
  • OpperSharp.Functions - AI-funktioner
  • OpperSharp.Indexes - Vector search/RAG
  • OpperSharp.Chat - Konversationer
  • OpperSharp.Spans - Tracing
  • OpperSharp.Agents - Multi-step AI

Plus Models-projekt för varje del

Varför så många projekt? Modularitet - ta bara vad du behöver Core är gemensam för alla, sen väljer du Functions, Indexes osv Models separat = clean separation, inga cirkulära beroenden .NET 8, nullable reference types enabled

Enklaste exemplet

using OpperSharp;

var client = new OpperClient("din-api-nyckel");

var result = await client.Functions.CallAsync(
    "translate-to-english",
    new { text = "Hej världen" }
);

Console.WriteLine(result.Message);
// Output: "Hello world"
Visa hur simpelt det är - 5 rader kod Jämför gärna med REST API om någon frågar (visa dokumentet med jämförelser) CallAsync returnerar typed result, inte bara dynamic JSON

Jämfört med direkt REST API

Med REST API

  • Skapa HttpClient
  • Sätt headers (API key, content-type)
  • Serialisera JSON manuellt
  • Hantera fel
  • Deserialisera svar
  • ~40-50 rader kod

Med OpperSharp

  • new OpperClient(key)
  • await client.Functions.CallAsync()
  • Klart.
  • ~5 rader kod
90% mindre kod - detta är den stora poängen! Allt error handling är inbyggt, retry-logik finns SDK hanterar rate limiting, timeout, allt sånt Du slipper tänka på HTTP-detaljer och kan fokusera på logik

Functions - AI-powered funktioner

// Anropa en function
var result = await client.Functions.CallAsync(
    "extract-entities",
    new { text = someText }
);

// Med context för RAG
var ragResult = await client.Functions.CallAsync(
    "answer-question",
    new { question = "Hur funkar OpperSharp?" },
    new OpperCallOptions
    {
        Context = new() { ["index_key"] = "documentation" }
    }
);
Functions = du definierar AI-funktioner i Opper UI, sen anropar du dem här Context-parametern gör RAG möjlig - koppla till en kunskapsbas Opper hanterar prompts, models, allt - du bara anropar Bra för: entity extraction, classification, summarization, Q&A

Streaming-stöd

await foreach (var chunk in client.Functions.StreamAsync(
    "generate-story",
    new { topic = "AI och framtiden" }
))
{
    Console.Write(chunk.Delta);
}

IAsyncEnumerable - fungerar precis som du förväntar dig i C#

Streaming är viktigt för UX - visa text medan den genereras IAsyncEnumerable är C# 8 feature, funkar perfekt med await foreach Delta innehåller nästa bit av texten Under huven: Server-Sent Events från Opper API

Indexes - för RAG

// Indexera dokument
await client.Indexes.IndexAsync(
    "documentation",
    new { content = "OpperSharp är...", metadata = ... }
);

// Sök semantiskt
var results = await client.Indexes.QueryAsync(
    "documentation",
    "Hur använder jag OpperSharp?"
);

// results innehåller relevanta dokument
RAG = Retrieval-Augmented Generation Kort: stoppa in dina dokument i index, sen kan AI-funktioner använda dem som context Semantisk sökning, inte keyword-baserad Metadata kan vara vad som helst - användbart för filtering Opper hanterar embeddings och vector search

Chat - konversationer

var response = await client.Chat.CreateAsync(
    new ChatRequest
    {
        Messages = new List
        {
            new() { Role = "user", Content = "Förklara OpperSharp" }
        },
        ParentSpanId = spanId  // för tracing
    }
);

Console.WriteLine(response.Message);
Chat API = för konversationer, inte single-shot som Functions Skicka in message history, få svar tillbaka ParentSpanId = koppla till spans för att tracka konversationer Användbart för chatbots, support, interaktiva assistenter

Spans - distributed tracing

Tracka vad som händer i dina AI-operationer:

var span = await client.Spans.CreateAsync(
    "user-query",
    new { query = userInput }
);

try
{
    // Gör AI-operationer med span.Id som parent
    var result = await DoAIStuff(span.Id);

    await client.Spans.UpdateAsync(span.Id, new { result });
}
catch (Exception ex)
{
    await client.Spans.UpdateAsync(span.Id, new { error = ex.Message });
}
Spans = som distributed tracing (tänk OpenTelemetry) Skapa parent span, sen child spans för varje operation Senare: se hela flödet i Opper UI Perfekt för debugging och observability Kan koppla spans till cost tracking också

Agents - multi-step AI

AI som kan använda verktyg och fatta beslut:

public class WeatherTools
{
    [Tool("Hämta väder för en stad")]
    public async Task GetWeather(string city)
    {
        // Din logik här
        return $"20°C och soligt i {city}";
    }
}

var agent = new Agent(client, new AgentOptions
{
    FunctionPath = "weather-assistant",
    Tools = Agent.DiscoverTools()
});

var result = await agent.RunAsync(
    new { question = "Hur är vädret i Stockholm?" }
);
Agents = AI som kan anropa C#-metoder (tools) för att utföra uppgifter [Tool] attribute = AI:n ser metodnamn och description Agenten bestämmer själv vilka tools den behöver anropa Multi-step: kan göra flera tool calls i sekvens MaxIterations förhindrar oändliga loopar Exempel: "boka möte" = kolla kalender, hitta tid, boka

Felhantering

try
{
    var result = await client.Functions.CallAsync(...);
}
catch (OpperException ex)
{
    Console.WriteLine($"API fel: {ex.Message}");
    Console.WriteLine($"Status: {ex.StatusCode}");
}
catch (HttpRequestException ex)
{
    // Nätverksproblem
}

Custom exceptions för olika typer av fel

OpperException för API-specifika fel (400, 404, 500 etc) Innehåller StatusCode och response body om möjligt SDK hanterar retries automatiskt för 429 och 5xx Du behöver bara hantera faktiska fel i din logik

Saker som inte finns i Python SDK

  • CRUD för Functions och Indexes - skapa/uppdatera/ta bort
  • Bulk operations - indexera många dokument samtidigt
  • Retry-logik - inbyggd med exponential backoff
  • Convenience methods - enklare syntax för vanliga saker
Detta är värdet av att bygga en egen SDK CRUD = du kan faktiskt skapa functions programmatiskt, inte bara i UI Bulk = effektivare än att loopa själv Retry = automatisk, konfigurerbar Convenience = typ WithTools() builder pattern för agents

Komplett exempel: RAG-baserad Q&A

// 1. Indexera dokumentation
await client.Indexes.IndexAsync("docs",
    new { content = docText, source = "readme.md" }
);

// 2. Anropa function med index som context
var answer = await client.Functions.CallAsync(
    "answer-question",
    new { question = "Hur konfigurerar jag agent tools?" },
    new OpperCallOptions
    {
        Context = new() { ["index_key"] = "docs" }
    }
);

// 3. Få intelligent svar baserat på faktisk dokumentation
Console.WriteLine(answer.Message);
Detta är typiskt use case: Q&A över egen data Indexera = embeddings skapas och lagras Context med index_key = Opper hämtar relevanta dokument först AI:n får context + question, svarar baserat på faktisk info Bättre än att bara GPT:a - grounded i din data

Tips när du använder SDK:n

  • Använd using för OpperClient (implements IDisposable)
  • Sätt timeout i HttpClient om du har långsamma operations
  • Använd spans för observability från början
  • Cache funktions-resultat där det är meningsfullt
  • Testa med mock data innan du anropar riktiga AI-endpoints
using = ensures proper disposal av HTTP connections Timeout viktigt för streaming operations Spans undervärderade - lägg till direkt, tacka mig senare Caching: Opper har cache på serversidan också (Cache = true i options) Mock: bygg interface för OpperClient om du vill unit testa

Varför behövs en C# SDK?

Bra fråga! Några skäl:

  • .NET är stort inom enterprise
  • Azure Functions, ASP.NET, Blazor - vill använda Opper där
  • Type safety är värdefullt vid större projekt
  • Många utvecklare känner sig mer hemma i C#
Enterprise = banker, försäkring, myndigheter kör ofta .NET Azure Functions med Opper = serverless AI, ganska coolt ASP.NET = backend för web apps som behöver AI Type safety viktigare i stora teams än solo-projekt Comfort = produktivitet, folk jobbar snabbare i bekant miljö

Begränsningar och saker att tänka på

  • Beroende av Opper API (kostar pengar)
  • SDK:n är inte officiellt supportad av Opper
  • Ännu inte på NuGet (måste bygga själv)
  • Dokumentationen kunde vara bättre
  • Inga omfattande unit tests än
Ärligt om begränsningar - viktigt att vara transparent Opper kostar = inte gratis, men free tier finns för testing Inte officiell = jag håller det, inte Opper team NuGet = arbete att publicera och underhålla Docs = finns XML comments men kunde ha mer guides Tests = finns integration tests men inte 100% coverage
