Problemet: REST API Komplexitet


var httpClient = new HttpClient {
    BaseAddress = new Uri("https://api.opper.ai")
};
httpClient.DefaultRequestHeaders.Authorization =
    new AuthenticationHeaderValue("Bearer", apiKey);

var requestBody = new { input = new { question = "Vad är AI?" } };
var content = new StringContent(
    JsonConvert.SerializeObject(requestBody),
    Encoding.UTF8, "application/json"
);

var response = await httpClient.PostAsync("/v1/call/func", content);
var responseString = await response.Content.ReadAsStringAsync();

if (!response.IsSuccessStatusCode) {
    throw new Exception($"API-fel: {responseString}");
}

var result = JsonConvert.DeserializeObject<dynamic>(responseString);

~50 rader boilerplate-kod!

Speaker Notes - REST API Komplexitet

  • Detta är vad du måste göra UTAN OpperSharp
  • Skrolla långsamt genom koden och påpeka problempunkter:
  • 1. HTTP-klient setup - måste göras för varje projekt
  • 2. Headers - lätt att glömma eller göra fel
  • 3. JSON-serialisering - manuell och felbenägen

  • Inga retries, ingen caching, ingen type safety
  • Fråga: "Vem vill skriva detta om och om igen?" (retorisk)

Speaker Notes - Functions API

  • Functions är kärnan i Opper - AI-drivna uppgifter
  • Exemplet visar dokumentsammanfattning
  • Gå igenom parametrarna:
    • path: Namnet på funktionen (skapad i Opper)
    • input: Dina data (typ-säkert Dictionary)
    • options: Valfria inställningar
  • OpperCallOptions exempel:
    • Model: Välj AI-modell (gpt-4, gpt-3.5, etc.)
    • Temperature: Kreativitet (0.0-1.0)
    • Cache: Spara kostnader genom att cacha resultat
  • Response ger både Message och metadata (Cached, SpanId, etc.)
  • Real-world exempel: Dokumentsammanfattning, översättning, dataanalys

2. Indexes API

Bygg Kunskapsbaser


// Skapa index
var index = await client.Indexes.CreateAsync(
    name: "företagsdokument",
    description: "Intern dokumentation"
);

// Lägg till dokument (bulk)
await client.Indexes.AddBulkAsync("företagsdokument", new[] {
    new OpperDocument {
        Content = "Semesterpolicy: 20 dagar per år",
        Metadata = new() { ["category"] = "HR" }
    },
    new OpperDocument {
        Content = "Kodgranskning kräver 2 godkännanden",
        Metadata = new() { ["category"] = "Engineering" }
    }
});

Speaker Notes - Indexes API

  • Indexes = din egen AI-driven kunskapsbas
  • Vektordatabas under huven - semantisk förståelse
  • Inte bara keyword-sökning - förstår mening och kontext
  • Användningsfall:
    • Dokumentation-assistenter
    • FAQ-bots
    • Kunskapsbaser för företag
    • RAG (Retrieval-Augmented Generation)
  • AddBulkAsync = effektivt, ett API-anrop för många dokument
  • Python SDK har inte bulk support!
  • Metadata = filtrering och kategorisering
  • Exempel: "Sök efter semesterpolicy" hittar även "ledighet" och "vacation"

Indexes: Semantisk Sökning


var results = await client.Indexes.QueryAsync(
    indexName: "företagsdokument",
    query: "Hur många semesterdagar?",
    k: 5
);

foreach (var result in results.Results)
{
    Console.WriteLine($"[{result.Score:F2}] {result.Content}");
}

Resultat:

[0.92] Semesterpolicy: 20 dagar per år
[0.34] Förmånsöversikt...

Speaker Notes - Semantisk Sökning

  • Query = ställ frågor på naturligt språk
  • k = antal resultat (top-k)
  • Score = relevans (0.0-1.0, högre är bättre)
  • Notera: Frågan "Hur många semesterdagar" matchar "20 dagar per år"
  • Detta är semantisk förståelse, inte keyword matching
  • AI förstår att "semesterdagar" ≈ "vacation" ≈ "ledighet"
  • Kan kombineras med filters (metadata)
  • Exempel: query="vacation" + filter={"category": "HR"}
  • Poäng: "Som att ha en expert som läst all dokumentation"

5. Agent-Ramverk


public class MathTools
{
    [Tool("Adderar två tal")]
    public double Add(double a, double b) => a + b;

    [Tool("Multiplicerar två tal")]
    public double Multiply(double a, double b) => a * b;

    [Tool("Beräknar procent")]
    public double Percentage(double value, double percent)
        => value * (percent / 100);
}

Attribut-baserad verktygsupptäckt!

Speaker Notes - Agent Framework - Verktyg

  • Agents = AI som kan använda verktyg automatiskt
  • Detta är MYCKET kraftfullt - AI bestämmer VILKA verktyg som behövs
  • [Tool] attribut = precis som Python's @tool decorator
  • Beskrivningen är viktig - AI läser den för att förstå verktyget
  • Typsäkerhet = parametrar valideras automatiskt
  • Kan ha sync eller async metoder
  • Verktyg kan vara vad som helst:
    • Databassökningar
    • API-anrop
    • Beräkningar
    • Filoperationer
  • Viktigt: AI väljer verktyg baserat på användarfrågan

Agent-Användning


var agent = new Agent(client, new AgentOptions {
    FunctionPath = "math-solver",
    MaxIterations = 10

var response = await agent.RunAsync(
    "Om jag investerar 1000 kr med 15% avkastning, " +
    "sedan lägger till 500 kr, vad blir totalen?"
);

Console.WriteLine($"Svar: {response.Output}");
Console.WriteLine($"Iterationer: {response.Iterations}");

Iterationer: 3

Speaker Notes - Agent Användning

  • Här ser vi agenten i aktion
  • Användaren ställer en komplex fråga
  • Agenten bryter ner det i steg:
    1. Beräkna 15% av 1000 (Percentage tool)
    2. Addera resultatet till 1000 (Add tool)
    3. Addera 500 till summan (Add tool igen)
  • MaxIterations = säkerhetsgräns, stoppar oändliga loopar
  • Response visar antal iterationer och vilka verktyg som användes
  • Automatisk orkestrering - ingen manuell loop-kod
  • Inbyggd tracing om EnableTracing = true
  • Real-world: Dataanalys, automation, komplex problemlösning
  • Demo-tips: Visa olika frågor och hur agenten anpassar sig

Verkligt Exempel: RAG-Pipeline


// Steg 1: Sök kunskapsbas
var searchResults = await client.Indexes.QueryAsync(
    indexName: "företagsdokument",
    query: "Vad är vår kodgranskningsprocess?",
    k: 3
);

// Steg 2: Bygg kontext
var context = string.Join("\n\n",
    searchResults.Results.Select(r => r.Content));

// Steg 3: Generera svar med kontext
var answer = await client.Chat.CompleteAsync(
    prompt: "Vad är vår kodgranskningsprocess?",
    systemPrompt: $@"Svara endast med denna kontext:
{context}
Om inte i kontext, säg 'Jag har inte den informationen.'"
);

Console.WriteLine(answer);

Speaker Notes - RAG Pipeline

  • RAG = Retrieval-Augmented Generation
  • Mycket viktigt mönster för enterprise AI
  • Kombinerar 3 APIs: Indexes, Chat, och implicit Spans
  • Steg-för-steg:
    1. Sök relevant info i kunskapsbas (semantisk sökning)
    2. Samla ihop resultaten till kontext
    3. Ge AI både frågan OCH kontexten
    4. AI svarar baserat på FAKTA, inte "uppfinning"
  • Varför RAG?
    • Reducerar "hallucinations" (AI som hittar på)
    • Ger källhänvisningar
    • Håller data uppdaterad
    • Ingen omträning av modeller behövs
  • Användningsfall: Dokumentation-bots, FAQ-system, research-assistenter
  • Poäng: "Så här bygger man pålitliga AI-system"

Speaker Notes - Jämförelse

  • Detta är viktigt - vi är INTE sämre än Python SDK
  • 100% feature parity = allt Python kan, kan vi också
  • Men vi har MER:
    • Full CRUD = Create, Read, Update, Delete för allt
    • Python har begränsad update/delete funktionalitet
    • Bulk operations = effektivare, färre API-anrop
    • Python måste loopa = många API-anrop = långsammare
    • Retry logic = inbyggd, konfigurerbar, exponential backoff
    • Python måste implementeras manuellt = mer kod
  • Plus: Type safety, IntelliSense, compile-time errors
  • Poäng: "Vi är inte bara jämbördiga - vi är bättre på flera områden"

Speaker Notes - Best Practices

  • Tips från produktion-erfarenhet
  • 1. using = frigör resurser korrekt
    • using var client = ... eller using (var client = ...)
    • Viktigt i ASP.NET och services
  • 2. Caching = spara pengar och tid
    • Cache = true i options
    • Bra för statiska frågor/dokument
    • Reducerar API-kostnader
  • 3. CancellationToken = timeout protection
    • Viktigt i web apps (användarens request timeout)
    • Prevent hanging operations
  • 4. Specifika exceptions = bättre felhantering
    • 404 = resurs finns inte (skapa den?)
    • 429 = rate limited (vänta och försök igen)
    • 500 = server error (retry automatiskt)
  • 5. Bulk = effektivitet
